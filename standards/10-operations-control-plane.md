# 10 运维观测与控制面职责边界规范

> 本规范定义 Prometheus、Alertmanager、Loki、Grafana、AreaSong Ops、Git、系统调度器与共享 SSH 终端之间的长期职责边界。具体受管对象、指标、告警阈值、Dashboard、部署参数和凭据不属于本文档范围。
>
> 本规范描述稳定目标职责，不表示其中全部能力已经在生产实现；当前能力以代码、部署记录和验收证据为准。

## 1. 目的与适用范围

本规范用于避免观测、告警、处置、变更和审计能力重复建设，确保完整运维流程始终满足：

```text
采集事实 -> 判断异常 -> 形成告警 -> 通知人员 -> 定位原因
         -> 制定处置 -> 批准变更 -> 执行动作 -> 验证结果
         -> 回滚或收口 -> 留存审计
```

适用于：

- 平台观测、告警、日志、变更控制与审计。
- 应用、主机、凭据、自动任务、备份域和配置等受管对象。
- 新能力接入、生产变更、故障处置、恢复演练和对象下线。

不在本文档记录：

- 具体业务对象、域名、地址、端口、容器或版本。
- 具体指标名称、查询表达式、告警阈值或看板面板。
- 真实邮箱、用户数据、凭据、文件内容或单次部署证据。
- 可直接执行的生产命令和具体恢复步骤。

## 2. 核心原则

1. 一种状态只有一个权威来源；其他系统只能读取、投影或关联。
2. Prometheus 是告警规则的唯一来源，不建立第二套 Grafana 告警规则。
3. Alertmanager 是告警分组、抑制、静默和通知的唯一权威。
4. Grafana 负责观察和诊断，不执行生产变更。
5. AreaSong Ops 负责预检、计划、批准、执行、验证、恢复和变更审计，不复制趋势、日志或告警生命周期。
6. Git 是声明式非敏感配置的唯一期望状态来源。
7. 系统调度器负责周期调度，AreaSong Ops 不重新实现通用调度器。
8. 所有生产写动作必须类型化、目标固定、参数受限、可预检、可审计并有明确恢复边界。
9. 关键身份、授权、审计或恢复条件异常时，生产写动作必须 fail closed（拒绝执行）。
10. 共享 SSH 终端保留为控制面故障和未知事故的紧急通道，不在网页中提供超级模式。

## 3. 统一术语

| 术语 | 定义 |
|------|------|
| 观测事实 | 指标、日志和外部探测产生的客观运行数据。 |
| 观测事件 | 部署、重启、备份或恢复等用于关联趋势的时间点。 |
| 告警 | Prometheus 规则判断出的异常，由 Alertmanager 管理生命周期。 |
| 待处置事项 | 需要人工行动的告警投影及其处置关系，不是新的告警副本。 |
| 事故 | 已确认造成业务、数据或安全影响，需要持续跟踪的问题。 |
| 静默 | Alertmanager 中对匹配告警的限时通知抑制。 |
| 风险接受 | 在明确期限内接受尚未消除的风险，不等同于静默或问题解决。 |
| 受管对象 | 具有稳定身份、责任、生命周期和受控能力的逻辑对象。 |
| 能力 | Runner 允许执行的类型化操作契约。 |
| 操作预览 | 按当前状态计算的影响、风险和前置条件，短期有效。 |
| 变更计划 | 固定目标、当前状态、阶段、验证、恢复和策略摘要的不可变对象。 |
| 批准 | 对一个不可变计划摘要的限时授权。 |
| 执行任务 | 某个计划的一次真实执行实例。 |
| 恢复点 | 与对象和任务绑定、产物齐全且摘要验证通过的一组备份证据。 |
| 观察窗口 | 即时验证通过后，继续使用观测事实判断稳定性的时间段。 |
| 收口 | 身份、验证、观察、告警、静默、恢复能力和审计全部满足完成条件。 |
| 审计记录 | 对创建、批准、执行、拒绝、恢复、风险接受等治理行为的只追加记录。 |
| 策略例外 | 对一次明确动作、对象和期限放宽单一可配置门禁的记录。 |

告警恢复、任务成功、计划完成和事故关闭是四个不同状态，不能自动互相等同。

| 计算规则和产生告警 | 主责 | 接收 | - | 展示 | 只读投影 | Git 保存规则 |
| 分组、抑制、静默和通知 | - | 主责 | - | 管理界面 | 仅计划绑定静默 | Git 保存路由配置 |
| 趋势、关联日志和诊断 | 提供数据 | 提供状态 | 提供数据 | 主责 | 提供深链接 | Git 保存 Dashboard |
| 预检、计划和批准 | 提供证据 | 提供证据 | 提供证据 | 提供诊断 | 主责 | Git 保存策略和声明 |

| 期望配置 | - | - | - | - | 受控部署 | Git 主责 |

### 4.1 明确不负责

- Prometheus 不执行动作、不保存人工处置状态。
- Alertmanager 不负责根因诊断、生产执行或事故正文。
- Loki 不承担告警规则、审计权威或生产操作。
- Grafana 不提供重启、更新、回滚、清理、恢复和凭据轮换按钮。
- AreaSong Ops 不复制指标趋势、原始日志、完整告警管理、通用配置编辑或任务调度。
- Git 不保存秘密、动态运行状态、任务游标或用户数据。
- cron/systemd 不得独立执行改变生产版本、数据结构、权限或网络入口的动作。

## 5. 权威数据来源

| 状态 | 权威来源 |
|------|----------|
| 指标当前值与历史 | Prometheus |
| 日志原文 | Loki |
| 告警触发、恢复和静默 | Alertmanager |
| Dashboard 与诊断入口 | Git 管理的 Grafana 配置 |
| 生产实际身份 | 运行环境，由受控检查即时读取 |
| 期望身份和非敏感配置 | Git |
| 发布准备状态 | AreaSong Ops |
| 计划、批准和任务状态 | AreaSong Ops |
| 变更行为审计 | AreaSong Ops，定期异地归档 |
| 周期任务是否实际运行 | cron/systemd；Prometheus 检测结果新鲜度 |
| 凭据正文 | 专用密钥存储或 root-only 配置 |

AreaSong Ops 可以展示外部状态，但必须标明来源；外部来源不可用时显示“数据不可用”，不得显示为正常、零或已恢复。

## 6. 标准运维闭环

标准流程为：

```text
告警或人工发现
-> Grafana 定位指标、日志和影响范围
-> AreaSong Ops 形成待处置关系
-> 执行前检查
-> 创建不可变计划
-> 批准
-> 建立必要恢复点和维护静默
-> 执行类型化动作
-> 即时验证
-> 进入观察窗口
-> 解除静默并确认阻断告警恢复
-> 收口或创建恢复计划
-> 留存审计并关联事故或改进项
```

执行命令返回成功只代表执行阶段结束，不代表计划已经收口。

## 7. 告警、待处置事项与事故

### 7.1 告警职责

- Prometheus 判断是否异常。
- Alertmanager 管理告警分组、抑制、静默、通知和恢复。
- Grafana 展示活动告警并提供诊断。
- AreaSong Ops 只维护告警与计划、任务、Runbook 和事故的关联。

待处置事项可以读取全部活动告警，但默认只展示需要人工行动的项目。分类应来自 Git 管理的处置映射，而不是前端解析告警标题。

### 7.2 待处置分类

| 分类 | 含义 | AreaSong Ops 行为 |
|------|------|-------------------|
| 可受控处置 | 已有固定且安全的能力 | 允许创建计划 |
| 需人工处置 | 有 Runbook，但没有标准化动作 | 提供诊断、Runbook 和事故入口 |
| 仅观察 | 尚未达到行动条件 | 默认折叠并跳转 Grafana |

AreaSong Ops 不提供第二套告警状态、通用静默编辑器或手工修改告警级别。

### 7.3 事故跟踪

当前使用外部工作项系统跟踪需要持续协调的事故和改进项。AreaSong Ops 只保存提供方、引用编号和链接，不管理事故正文。

告警恢复时可以自动更新事故状态，但不得自动等同于事故关闭。事故关闭还需确认处置、结论和必要改进项已经落实。

## 8. 静默、观察与收口

### 8.1 静默边界

- 人工排障静默在 Grafana/Alertmanager 创建。
- AreaSong Ops 只能为已批准计划创建目标固定、范围精确、期限有限的维护静默。
- matcher 必须由对象和能力声明生成，用户不能自由输入。
- 永久静默禁止。
- 备份失败、回滚失败、审计失败、状态不确定和控制面故障告警不得被维护静默覆盖。

创建静默失败时，中高风险动作默认不开始。执行失败时先处理回滚；状态不确定时应提前解除静默，让真实故障重新暴露。

### 8.2 验证层级

1. 机制验证：操作本身成功。
2. 身份验证：运行身份和配置摘要符合计划。
3. 技术健康验证：health、依赖和固定 smoke 通过。
4. 业务结果验证：关键业务行为或数据一致性满足预期。

计划必须声明最高验证层级。无法自动证明的业务结果由授权人员确认并记录证据。

### 8.3 收口条件

计划只有同时满足以下条件才可完成：

- 执行任务具有明确终态。
- 目标身份、即时验证和必要业务验证通过。
- 观察窗口结束。
- 关联阻断告警已恢复或具有有效且明确的风险接受。
- 维护静默已解除或确认即将自动到期。
- 恢复点和任务证据完整。
- 不存在恢复状态不确定。
- 审计写入成功。

任务执行成功后计划进入“观察中”，不能直接标记为完整完成。

## 9. 计划、批准、任务与审计

### 9.1 对象关系

```text
动作声明 -> 操作预览 -> 变更计划 -> 批准记录
         -> 执行任务 -> 观察窗口 -> 收口或恢复计划 -> 审计
```

- 预览短期有效，可重新生成。
- 计划创建后不可编辑；内容变化时作废并新建。
- 批准只授权一个计划摘要，并有有效期。
- 任务表示一次真实执行，事件只追加。
- 观察属于计划，不应让任务长期保持运行中。
- 审计记录治理行为，任务事件记录技术过程，两者不能互相替代。

### 9.2 批准失效条件

以下任一变化都会使批准失效：

- 当前运行身份或目标摘要变化。
- 恢复点变化、无效或过期。
- 动作声明、适配器或策略摘要变化。
- 期望配置 revision 变化。
- 关键预检结果变化。
- 身份权限被撤销。
- 计划超期或已经执行。

### 9.3 幂等与并发

- 所有写 API 使用幂等语义，重复点击或网络重试不能重复执行。
- 同一受管对象最多运行一个写任务。
- 备份、恢复演练和生产恢复使用全局恢复资源锁。
- 主机重启与其他生产写任务互斥。
- 只读检查可并发，但必须限频。

### 9.4 失败分类

失败至少区分：尚未改变生产、已改变但可恢复、已回滚、需要恢复计划和恢复状态不确定。恢复状态不确定必须阻止关联对象的新变更，不能通过风险接受直接关闭。

## 10. 发布、更新与回滚

- 上游发布系统负责发布版本。
- 应用和定时任务可以发现、下载和验证版本，但不能独立 apply 到生产。
- 应用内部更新入口只能提交待审批请求或跳转 AreaSong Ops 计划。
- AreaSong Ops 是生产更新和版本回滚的唯一执行与审计入口。
- 生产执行必须重新验证当前身份、目标摘要、恢复点、准备证据和策略。
- 默认只改变声明的应用组件，依赖身份发生非预期变化时立即停止。
- 回滚目标必须来自已知成功更新的固定旧身份，不允许自由输入旧版本。
- 应用版本回滚不得隐式恢复业务数据库。

自动发现、验证和隔离准备可以启用；自动生产 apply 默认禁止。任何例外都必须采用独立策略和批准。

## 11. 备份、恢复与恢复演练

| 能力 | 主责 |
|------|------|
| 备份实现 | 固定受控脚本 |
| 周期调度 | cron/systemd |
| 新鲜度、完整性和失败检测 | Prometheus |
| 趋势和容量展示 | Grafana |
| 手动备份、恢复点、恢复演练与恢复审批 | AreaSong Ops |

- 备份作业成功不等于具备恢复能力。
- 恢复点必须绑定对象、任务、时间窗口、产物角色、大小和摘要。
- 恢复演练必须在隔离环境完成，不暴露生产端口、不访问生产写入口，并验证清理结果。
- 生产数据恢复是独立的最高风险计划，必须展示数据损失窗口、写入冻结、当前数据保全和验证方式。
- 被活动计划、回滚来源、未关闭事故或状态不确定任务引用的备份不得清理。
- 版本回滚、数据恢复和灾难恢复是三类不同动作。

## 12. 凭据轮换

AreaSong Ops 只提供类型化凭据轮换，不成为通用密钥库或环境变量编辑器。

轮换要求：

- 用途、目标、验证器、预期身份和权限范围固定。
- 新凭据仅通过 HTTPS、受认证 Web、Unix Socket 到 Runner 的内存路径传递。
- 不进入浏览器持久化、SQLite、日志、任务事件、Git 或备份。
- Runner 验证身份、权限和有效期后原子替换配置并执行 smoke。
- smoke 失败且旧凭据仍有效时恢复旧配置。
- 审计只保存凭据类型、短指纹、有效期、验证结论和结果。
- 旧凭据最终撤销由签发方完成；切换成功但尚未撤销时不能显示为完整收口。

无法验证权限、无法回滚或属于根身份的凭据不应接入网页轮换。

## 13. 主机操作与自动任务

### 13.1 主机操作

Grafana 负责主机趋势，AreaSong Ops 只执行固定主机动作。允许能力必须预先声明目标、风险、参数枚举、预检、执行、验证、超时和恢复说明。

适合逐项接入：只读基线检查、安全更新预检、清理预览、固定 unit 重启或 reload。主机重启、网络、权限和生产数据操作必须使用独立高风险流程。

### 13.2 自动任务

- cron/systemd 继续承担调度。
- Prometheus 检测任务是否按期成功。
- AreaSong Ops 只汇总已登记关键任务，并为少数固定任务提供受控补跑。
- 用户不能输入 unit、脚本路径、cron 表达式或命令参数。
- 修改调度策略属于 Git 配置变更。
- 会改变生产版本、数据结构、权限或网络入口的 timer 必须迁入 AreaSong Ops 计划闭环。

## 14. 配置管理

- Git 是声明式非敏感配置的唯一期望状态来源。
- AreaSong Ops 可以显示漂移、生成受 schema 限制的变更提案，并部署已审核 revision。
- AreaSong Ops 不提供原始 YAML、JSON、Compose、环境变量或任意文件编辑器。
- 计划必须绑定 commit、文件摘要、渲染摘要、目标环境和实际差异。
- 生产偏离 Git 时重新部署期望状态；紧急生产修改确认正确时，必须回填 Git 后重新建立一致性。
- 敏感配置只在 Git 中保存结构、权限和加载方式，真实值通过凭据轮换管理。

## 15. 身份、权限与批准

### 15.1 责任分层

- 外部身份代理负责认证和 MFA。
- AreaSong Ops Web 负责验证会话、Origin 和 CSRF。
- Runner 负责最终动作授权、风险和状态门禁。
- 前端按钮状态仅用于用户体验，不是安全边界。

### 15.2 基础角色

| 角色 | 职责 |
|------|------|
| viewer | 查看状态、计划、任务和脱敏审计。 |
| operator | 运行检查、创建计划和执行已批准的普通动作。 |
| approver | 批准中高风险计划和风险接受。 |
| security_operator | 执行凭据和安全类受控工作流。 |
| platform_admin | 管理角色映射和极高风险平台能力。 |

同一人员可以兼任多个角色，但创建、批准和执行仍是独立行为。权限必须结合主体、动作、对象、环境和风险判断，不能只按页面划分。

机器主体只能为自己的对象提交受限请求，不得批准、执行、读取审计或访问凭据能力。

## 16. 受管对象与能力扩展

### 16.1 受管对象

受管对象至少包含稳定身份、类型、显示信息、环境、责任、重要级别、生命周期、能力和观测链接。运行实例、容器名、IP 和显示名称不能作为治理主键。

### 16.2 类型化能力

能力模板负责风险、参数 schema、计划、批准、锁、阶段、超时、证据、恢复和前端交互；适配器只负责读取目标身份、执行固定机制和验证结果。

适配器必须通过受信注册表引用，禁止在声明中提供任意 command、Shell、executable、路径、环境变量或自由参数数组。

### 16.3 能力成熟度

```text
disabled -> inspect_only -> shadow -> manual_approval -> automated
```

新能力默认从只读开始，经过测试、隔离演练和生产验收后逐项开放。发现异常时可以降级成熟度，不需要删除历史声明。

## 17. 对象身份与标签契约

所有平台使用稳定 `object_id` 和受控基础字段关联。对象身份必须全局唯一、不随实例重建或地址变化，并在 Git 中声明。

跨系统最小契约根据数据类型选用：环境、主机、对象、对象类型、服务、组件、实例、责任域和重要级别。高变化字段不得成为治理主键。

告警进入处置闭环时应携带稳定对象身份、严重度、类别、处置分类和 Runbook ID。任务和计划使用不可变 ID；高基数任务 ID 不作为长期指标标签，只用于结构化日志、注释和深链接。

以下内容不得进入指标或日志索引标签：完整 URL、请求 ID、用户身份、凭据指纹、错误文本、SQL、日志正文、文件路径和任意外部输入。

## 18. 页面边界与深链接

### 18.1 Grafana

Grafana 页面围绕运行、可靠性、安全和治理组织，负责状态、趋势、日志、活动告警和控制面自监控。

### 18.2 AreaSong Ops

AreaSong Ops 页面围绕操作、变更、保障和治理组织，负责待处置事项、服务和主机操作、计划、执行、恢复、备份、凭据、自动任务和变更审计。

操作总览只突出待批准、运行中、观察中、恢复不确定、凭据到期和自动任务失败，不复制主机资源趋势或完整健康矩阵。

### 18.3 双向深链接

- Grafana 向 AreaSong Ops 传递对象、告警指纹和时间上下文，仅用于预填，不能授权或直接执行。
- AreaSong Ops 向 Grafana 传递对象、任务前后时间范围和固定 Dashboard UID，用于变更前后诊断。
- 两者不通过 iframe 互相嵌入。
- 链接参数使用稳定身份，不携带秘密或权限信息。

## 19. Runbook、通知与事故关联

### 19.1 Runbook

Runbook 由 Git 管理，使用稳定 ID，说明症状、只读诊断、处置顺序、安全边界、验证、恢复和事故升级条件。Markdown 中的命令不得被 AreaSong Ops 直接执行。

能力声明是机器执行契约，Runbook 是人类流程说明；两者通过 ID 关联但不能相互替代。Runbook 必须有责任人、复查时间，并通过实际演练保持有效。

### 19.2 通知

- Alertmanager 是运行告警的唯一通知编排器。
- AreaSong Ops 只通知计划、批准、任务、观察和恢复结果。
- 外部工作项系统负责持续事故和改进跟踪。
- 每日摘要承载非紧急信息，不替代实时严重告警。
- 各渠道通过告警指纹、计划、任务和事故 ID 关联，不重复发送同一事实。

## 20. 风险策略、冻结与例外

风险至少分为只读、低、中、高和极高。动作风险与告警严重度是不同概念。

最终风险由 Runner 根据平台最低风险、对象附加风险、生产影响、数据风险、范围、可逆性、验证能力、恢复能力、安全影响、成熟度、当前状态和时间条件计算。对象声明只能提高风险，不能降低平台最低要求。

必须硬约束且不可通过普通例外关闭：

- 身份认证和 Runner 授权。
- 审计可写。
- 秘密保护。
- 受信适配器验证。
- 请求完整性和幂等。
- 任意命令禁止。
- 状态不确定保护。
- 生产数据恢复的明确高风险确认。

变更冻结可以按全局、环境、对象或能力生效。例外必须限定对象、单一策略、原因、补偿措施、批准人和到期时间，不得自动续期。

风险接受、策略例外和维护静默是三种不同对象，不能共用“忽略”语义。

## 21. 对象生命周期

```text
proposed -> onboarding -> active -> maintenance -> retiring -> retired
```

- 新对象先登记身份、责任、观测、告警、Runbook、备份和凭据要求，再只读接入并逐项开放能力。
- 下线时先阻止新计划，处理活动任务和数据，再依次处理入口、运行组件、监控、告警、日志、备份、凭据和自动任务。
- 监控应在下线末期移除。
- 已被告警、计划、任务、事故或审计引用的对象只能退休，不能删除。
- 运行发现的未登记资产进入人工确认，不自动纳管或删除。

## 22. 数据保留、审计与灾难恢复

### 22.1 数据分层

- Git 保存期望配置。
- AreaSong Ops 数据库保存运行状态、计划、任务和近期审计。
- 操作产物存放在受控目录并使用引用保护。
- 审计摘要定期形成带连续摘要的异地只读归档。
- 秘密、指标和日志分别采用独立存储与保留策略。

短期详细事件、中期任务证据和长期审计摘要使用不同保留等级；秘密正文、请求体和临时秘密不保留。

### 22.2 控制面恢复

控制面应能从 Git revision、固定构建、root-only 配置、状态快照、操作产物索引和审计归档重建。状态快照必须使用数据库一致性机制并验证完整性、schema、序号和活动任务。

恢复后先以只读模式启动并重新读取生产实际状态。任何可能已改变生产的未终结任务不得自动重试。控制面恢复演练与业务数据恢复演练必须独立进行。

## 23. 可用性、资源与降级

- 业务运行、周期备份和核心调度不依赖 AreaSong Ops Web。
- Grafana、Loki、Alertmanager、Prometheus 和 AreaSong Ops 应能独立降级。
- 观测依赖不可用时，只读能力可以继续；需要相应证据的中高风险动作暂停或不能收口。
- 审计、身份、授权、锁或恢复状态异常时所有写动作停止。
- 单机环境优先保证可重建、外部探活、异地备份、开机恢复和共享 SSH，不在同一主机堆叠伪高可用。

所有组件和能力必须声明资源上限、最大并发、超时、保留、临时空间和降级方式。资源优先级为业务、事故恢复、核心监控、生产备份、受控变更、日志审计、报表扫描和低优先级演练。

资源紧张时暂停低优先级扫描、清理和演练，不能牺牲业务、核心告警或必要备份。

## 24. 隐私与数据边界

平台采用最小数据原则：

- Prometheus 保存聚合数值和低基数稳定标签。
- Loki 保存源端脱敏日志。
- AreaSong Ops 保存结构化执行摘要和必要证据。
- 告警、邮件和外部工作项只传播最小必要摘要。
- Git 只保存非敏感声明、代码和文档。

秘密不得进入指标、标签、日志、任务事件、审计、Git、邮件、外部工作项或备份。脱敏必须在数据持久化和外发之前完成，不能只在前端隐藏。

用户标识、访问行为和内部拓扑属于敏感数据，应限制权限、缩短保留并优先聚合。操作者稳定 ID 应使用不可枚举的内部标识或带独立密钥的 HMAC，不依赖可枚举输入的普通哈希。

## 25. 测试、演练与发布门禁

测试必须覆盖：

- schema、引用、权限和策略静态验证。
- Runner 的计划摘要、批准失效、锁、幂等、状态机、审计和崩溃恢复。
- 适配器的输入限制、路径保护、超时、失败、回滚和脱敏。
- Web 的刷新恢复、实时连接、重复提交、权限、分页和响应式布局。
- 告警规则的触发、不触发、恢复、标签、抑制和模板。
- Dashboard 的 UID、查询、标签、深链接、注释、空状态和浏览器渲染。
- 备份、迁移、回滚和清理的隔离演练。
- 控制面恢复和未终结任务分类。

生产写能力必须按 `disabled -> inspect_only -> shadow -> manual_approval -> automated` 晋级。没有失败注入、隔离演练、监控、Runbook、回滚和生产验收，不得宣布完成。

## 26. 永久禁止事项

AreaSong Ops 和 Grafana 永久禁止提供：

- 网页 Shell、Web SSH 或自定义命令执行。
- 任意文件浏览、上传、下载、编辑或删除。
- 通用 Compose、Docker、systemd 或包管理控制台。
- 通用环境变量或原始配置编辑器。
- 裸 Docker Socket 暴露给 Web。
- 第二套 Prometheus 告警规则或 Alertmanager。
- 通用 cron/timer 调度器。
- 用户输入 executable、主机路径、环境变量名或任意参数数组。
- 自动生产数据库恢复。
- 根据自由文本日志自动执行命令。
- 永久静默或无期限策略例外。
- 绕过身份、授权、审计、秘密保护或状态不确定门禁的超级模式。

## 27. 文档治理

本文档描述稳定目标职责。当前实现差距、阶段计划、部署记录和具体对象配置应分别维护，不得将“计划实现”写成“当前已实现”。

每个职责章节遵循：目标、主责系统、允许能力、禁止能力、权威来源、协作关系、降级方式和完成标准。

以下变化必须评估是否更新本规范并记录架构决策：

- 新增或转移平台职责。
- 新增对象或能力类型。
- 改变身份、权限、风险或数据流。
- 改变恢复、审计或紧急访问方式。
- 放宽永久禁止事项。

普通对象接入、阈值调整和 Dashboard 面板变化通常不修改本规范。
