# 05 变更管理

> 单人运维的变更流程：Git 提交 = 变更审计，Warp 批准 = 审批流。

## 变更分级

| 级别 | 定义 | 示例 | 流程 |
|------|------|------|------|
| L0 只读 | 无副作用 | 查看日志、状态查询 | 直接执行 |
| L1 低风险 | 单服务、可快速回滚 | 配置 reload、容器重启 | 说明 → 批准 → 执行 → 验证 |
| L2 中风险 | 多服务或需短暂中断 | 版本升级、数据库迁移 | 备份 → 说明 → 批准 → 执行 → 验证 |
| L3 高风险 | 不可逆或影响全局 | 数据库 schema 变更、集群变更 | 完整变更计划 → 批准 → 执行窗口 → 验证 → 复盘 |

## 标准变更流程

```
备份 → 说明(做什么/为什么/影响/回滚) → 批准 → 执行 → 验证 → 记录 → git 提交
```

### 1. 备份

- 配置文件：`cp <file> <file>.bak.$(date +%Y%m%d)`
- 数据库：确认最近备份可用（见 06-backup-dr.md）
- Compose：记录当前镜像版本 `docker compose images`

### 2. 说明

向用户说明（Warp 中等待批准）：

- **做什么**：具体命令和操作
- **为什么**：变更原因
- **影响范围**：哪些服务/机器受影响，预计中断时间
- **回滚方案**：如何恢复到变更前状态

### 3. 执行

- 一次只做一个变更
- Ansible 变更先 `--check --diff` 预演
- Terraform 变更先 `plan` 看 diff

### 4. 验证

- systemctl status / docker ps / kubectl rollout status
- 健康检查端点
- 业务功能抽测
- 日志无异常

### 5. 记录

- 更新 inventory/ 台账（如涉及新服务/端口/机器）
- git commit，message 格式：`[change] 描述变更内容`
- 重大变更（L2/L3）填写变更记录

## 回滚预案模板

```markdown
## 变更：{简述}
- 日期：{YYYY-MM-DD}
- 级别：L{0-3}
- 操作人：{name}

### 变更内容
{具体做了什么}

### 回滚步骤
1. {步骤1}
2. {步骤2}

### 验证回滚成功
- {检查项}
```

## 紧急变更

生产故障时的变更：

1. **先止血**：回滚/重启/切流量（仍需批准，但主动快速给方案）
2. **再查根因**：只读排查
3. **事后复盘**：使用 `runbooks/postmortem-template.md`

## 禁止

- 一次批准当作长期授权
- 未经批准执行变更类命令
- 跳过验证直接进入下一步
- 遇到非预期输出自行换方案重试
