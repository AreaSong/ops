# sub 分流只读检查器与日常使用说明

独立入口，使用 Python 3.9+ 与已有 PyYAML；本机验证为 `/usr/bin/python3` 3.9.6 / PyYAML 6.0.3。不安装依赖，不导入 `clash-direct`，不创建状态目录或缓存，不执行扩展脚本。

## 日常使用与手动备用

截至 **2026-10-03（北京时间）**：Clash Verge 2.5.5 / Mihomo v1.19.31，`rule` 模式、TUN 开启。`sub` 已保留原 UID 原位转为本地订阅，自动刷新关闭；双节点已接入，默认及当前选择均为洛杉矶。已完成国内/境外分类、国内 DNS 补充、两条 Azure/OpenAI 精确规则优先级修正、只读检查器及回归测试、人工更新验收与分类恢复流程。

日常按现有规则国内直连、境外代理，保持洛杉矶即可；学校、手动直连和既有业务例外优先于通用分类。主组仅含洛杉矶、新加坡；八个境外业务组仅跟随主组，境外分类、gfw 与 fallback DNS 引用主组。临时直连的添加、删除及撤销统一见 [直连工具使用说明](../clash_direct/README.md)，不在此重复操作手册。

以下供使用者需要备用时手动操作，本次文档收尾不执行切换：

1. 运行下文离线与运行态检查，逐项核对基线；确定问题或新增必要未知应先查明。
2. 唯一主要切换入口是 **“🚀 节点选择”**：选择 **“🇸🇬 新加坡｜E-IX 01”**，然后在 **订阅 → sub → 重新激活订阅** 重新应用本地来源。不要使用远程更新代替重新激活。
3. 确认选择已保存、重新激活后仍保持新加坡，再运行两项检查验收；按下文解释 DNS 必要未知，不以退出 2 笼统放行。若保存与运行选择不一致或出现确定问题，停止后续变更并保留结果，不自动修复。
4. 返回洛杉矶同样在主组选择 **“🇺🇸 洛杉矶｜VMess · WS · TLS”**、重新激活本地 sub 并检查。日常返回只恢复主组选择并重新应用，不恢复旧来源备份。

切换影响跟随主组的新连接，旧连接可能继续存在或重连；不保证旧连接全部清除，也不承诺自动切换或主节点故障时备用一定可用。

## 节点、规则与 Geo 数据维护

| 对象 | 维护责任与边界 |
|---|---|
| 本地节点与基础规则 | 由本机维护者人工维护本地 sub 及关联扩展；本地订阅不会自动获得最新节点和规则。更新后按本文人工验收流程检查。 |
| 新加坡备用 | 来自较旧的 E-IX 保存来源（2026-06-08），刷新曾返回 403。复制到本地 proxies 扩展后不会跟随 E-IX 自动更新；需人工同步并核对来源与扩展一致。短期连接成功不证明实时账户状态或长期可用性。 |
| GeoSite / GeoIP | 分类域名和 IP 数据独立维护；维护者另行核对数据版本、更新设置及变更后的分流。sub 本地化不等于这些数据已更新，检查器也不展开其完整内容。 |

来源级恢复须按明确变更单元进行，核实恢复点属于本地化前、单节点还是双节点阶段，再按“恢复哪些来源”处理受影响部分；不要把某个旧时间戳备份作为永久恢复步骤。不得整体覆盖索引、其他订阅或热覆盖 `cache.db`。当前没有自动业务验收或自动恢复。

## 检查入口

在仓库根目录运行：

```sh
# 默认离线：仅读取当前索引、关联来源及生成配置。
/usr/bin/python3 -B scripts/local/clash_audit/clash_audit.py
# 同一离线检查的结构化输出。
/usr/bin/python3 -B scripts/local/clash_audit/clash_audit.py --json
# 显式读取本机内核状态，结果仍可能是 incomplete。
/usr/bin/python3 -B scripts/local/clash_audit/clash_audit.py --runtime
# 运行态 JSON，供后续阶段读取。
/usr/bin/python3 -B scripts/local/clash_audit/clash_audit.py --runtime --json
# 隔离夹具或另一个本地数据目录；默认仍然离线。
/usr/bin/python3 -B scripts/local/clash_audit/clash_audit.py --app-dir /path/to/fixture --json
# 无法发现进程参数时，手动指定已经核实的本机 Unix socket。
/usr/bin/python3 -B scripts/local/clash_audit/clash_audit.py --runtime --socket /absolute/path/to/core.sock
```

默认数据目录为当前用户 `Library/Application Support/io.github.clash-verge-rev.clash-verge-rev`。从 `profiles.yaml` 中唯一选择名为 `sub` 的订阅，再按其引用定位所有扩展。UID、节点显示名和规则总数都不是固定门禁。sub 未启用时停止对生成配置/内核归属的判断，返回未验证，不把“存在”视为“生效”。文件缺失、损坏、重复 YAML 键或关联不唯一均不能通过。

规则检查覆盖国内/境外分类的唯一性、目标及其位于 `GEOIP,CN`、`MATCH` 前的相对顺序，两条 Azure AI 精确规则与可确定的 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、MATCH 遮挡。允许更早的私网/IP 例外，不要求所有 GEOIP 都在分类之后。检查已知规则目标、组候选与 provider 的悬空引用。学校 `guat.edu.cn` 来自当前关联规则扩展；手动直连清单只读取现有 v1 JSON 数据区，空清单有效。拦截、Apple、微软服务与游戏规则段对照当前订阅来源的内容及顺序。

DNS 检查显式启用、国内显式 DIRECT 的阿里/腾讯 DoH、国内先于境外及 gfw 分类、关联 DNS 扩展中的定向例外、现有腾讯例外和境外出口引用。保留的规则例外必须先于国内/境外通用分类；生成配置中的 dialer-proxy 也检查悬空引用，相关链式出口仍标记未验证。这里的国内 DoH 清单是本阶段约定；以后有意更换服务时需审阅更新判据。不会发送 DNS 或网站探测。

运行态仅从唯一 Mihomo 进程的 `-ext-ctl-unix` 参数发现 socket（支持含空格路径），不照搬 GUI 配置或历史路径。发现失败时不会猜测，可用 `--socket` 明确指定。只使用 AF_UNIX 和固定 `/version`、`/configs`、`/rules`、`/proxies` 四个 GET；不连接 TCP 控制地址，不跟随重定向、不提权、不重试认证。认证值只在内存读取生成配置的 `secret` 并用于本机请求；失败时不更换凭据。每次请求超时 3 秒、响应上限 16 MiB。输出不包含凭据、节点配置、订阅地址、原始响应或异常栈。

运行态核对模式、关键规则及保留例外的相对顺序、`extra.disabled`、AI/节点选择/境外 DNS 引用的选择链。应终止于同一个当前配置中的具体代理节点；不以显示名推断洛杉矶或实际物理位置。DIRECT、循环、缺失选择会报问题；Relay、LoadBalance、dialer-proxy 或未知类型无法唯一确定出口时报告未验证。若 `/configs` 不暴露 DNS，则运行态 DNS 一致性为必要未验证项，**退出码 2、`runtime_verified=false`**；读取磁盘上的运行配置也不能替代内存加载证据。

## JSON 与退出码

默认人类输出先解释验收结论，再汇总各状态数量，只展开问题、提醒与未验证项；必要未知项标为 `[必要未验证]`。`--json` 输出全部检查详情。JSON 为单个对象，`schema_version:1`。`checks` 每项包含 `scope`、稳定 `code`、`status`、中文 `message`、`required`；用 `scope + code` 定位检查项，不要依赖文案判断结果。

| 退出码 | 顶层 status | 含义 |
|---|---|---|
| 0 | `passed` | 请求范围内必要检查通过；仍须阅读非必需的限制项 |
| 1 | `issues` | 发现结构或运行态问题；优先于同时存在的未验证项 |
| 2 | `incomplete` | 无已确认问题，但输入、文件、依赖、控制接口或必要证据不足 |

检查状态为 `pass`（通过）、`issue`（问题）、`warning`（提醒）、`unverified`（未执行/无法验证）。`required:false` 的提醒和范围外验证不改变退出码。`ok` 仅等价于退出码 0，不等于每项检查都通过。`all_checks_passed` 在存在任何提醒/未验证项时为 false。

`active` 为 true/false；无法识别时为 null。`runtime_requested` 表示显式请求；`runtime_observed` 表示已读取并检查四个接口的相关状态；`runtime_verified` 仅在没有问题或必要缺口、sub 启用且全部运行态项通过时为 true。离线永远为 false。`--help` 为人类可读说明并退出 0；Ctrl-C 遵循 Python 中断退出行为，不属于 JSON 检查结果。

### 如何阅读验收结果

| 已有逐项证据 | 人工结论与下一步 |
|---|---|
| 任意 `issue`，即使同时有 DNS 未知 | 已确认存在问题。停止后续变更，按输出的 `scope.code` 定位不满足的条件；规则目标、顺序或启用状态错误会影响对应分流。另行明确处理范围，先处理确定问题，再处理未知项；工具不修复或回滚。 |
| 必要离线项通过，未请求运行态 | “离线检查通过，尚未观察运行态”。退出 0 仅覆盖离线，不能宣布应用验收通过；继续运行 `--runtime`。 |
| 已观察运行态，其他运行态项通过，唯一必要未知项为 `runtime.dns_unexposed`，且没有问题 | “关键分流运行态检查通过；内核 DNS 加载状态未验证”。完整运行态验收未完成，退出 2、`runtime_observed=true`、`runtime_verified=false`。字段不暴露既不证明加载成功，也不证明 DNS 故障。 |
| 还有其他必要未知项 | 分别查看每个 `[必要未验证]`，例如 `runtime.disabled_unknown`、`runtime.runtime_unavailable`；不得统一归因于 DNS。接口不可用时 `runtime_observed=false`，不代表已经观察运行态。 |

非必要的静态限制、可达性和历史基线提醒仍需阅读。不要只根据退出码或某个布尔字段作验收决定；这些结论来自现有逐项证据，没有新增 JSON 状态体系。

## 手动更新验收与恢复

以下是未来变更时的人工流程，不是检查器执行的动作，也不构成本次活动配置变更授权。检查器始终不执行备份、下载、应用、恢复、流量切换或扩展脚本。

### 三种动作的边界

| 动作 | 实际影响 |
|---|---|
| 在独立副本准备候选 | 活动来源保持原样。可用 `--app-dir` 检查完整副本中的索引、关联来源和生成配置；本工具不会运行候选 JS 或生成候选 YAML。仅替换副本中的 JS 而保留旧生成文件，不能证明新脚本输出正确。 |
| 在活动脚本编辑器保存 | 保存当前脚本可能立即触发生成和应用，属于实际变更，不能作为离线预览或语法试验。 |
| 更新远程订阅 | 先保存下载内容，再生成和应用当前订阅；即使内核校验失败，已保存的远程内容也不会随之撤销。 |

能力依据为阶段 2B-1 对 Clash Verge **v2.5.5** 官方提交 `22e3f1ac8aefe4102ae2eb646a11a1ec614e8576` 的静态调查：`src-tauri/src/feat/profile.rs`、`src-tauri/src/enhance/{mod,script}.rs`、`src-tauri/src/core/manager/config.rs`、`src-tauri/src/cmd/save_profile.rs`。没有进行真实故障注入。脚本抛错或返回值无法解析时会回退到该脚本执行前的输入继续处理，不能保证保留旧运行配置；内核语法校验也不保证业务分流完整。重新激活不下载订阅，但会执行扩展。Boa 扩展环境没有 Node.js、文件系统或外部 CLI 能力；未找到受支持的更新前后验收 Hook，也未确认局部脚本日志的 GUI 入口。版本变化后需重新核实相关能力。

### 操作顺序

1. **确认目标和基线**：从当前 `profiles.yaml` 确认唯一 sub、当前启用项、实际订阅文件及 script/merge/rules/proxies/groups 引用。运行本文离线与运行态命令；核对当前应用/内核版本，保留脱敏结果和受影响业务现状。不要用历史 UID、路径、规则数或行号代替当前证据。存在确定问题或其他必要未知项时先查明；仅 DNS 未暴露也须明确记录为验收缺口。
2. **明确并批准变更单元**：列出目标、动作、时间窗口、影响、备份范围、验收标准、失败触发条件和恢复范围。脚本编辑与远程更新分别列明；恢复是否包含重新应用须预先写清。仅 DNS 未暴露不能自动判定失败并触发恢复，也不能自动判定完整成功。
3. **按变更类型备份来源**：在已批准范围内保存下表所列材料，记录原路径、对应 UID、时间及摘要，验证可读和关联完整。备份可能含凭据，只留在受保护的本地位置，不粘贴到日志或交接中。缺少可用恢复材料时不进入应用步骤。
4. **离线准备候选**：在独立副本编辑；完整副本需保留索引及所有关联文件，并有与候选对应的生成配置，才能检查其一致性。用 `--app-dir` 离线检查，不带 `--runtime` 去比较尚未应用的候选与活动内核。若没有已核实的隔离生成能力，明确保留“候选脚本执行结果未验证”，不能拿旧生成文件的通过结果替代。普通 GUI 更新不能被此步骤自动拦截。
5. **批准范围内应用**：准备完成后才在活动编辑器保存，或执行已批准的远程订阅更新；等待应用稳定，再继续验收。发生失败或状态不明时先收集只读证据，不连续重试写入，不扩大修改范围。
6. **运行检查器验收**：对活动数据目录运行离线和 `--runtime`，必要时同时读取 JSON。按上表区分确定问题、离线证据、仅 DNS 缺口及其他必要未知；本工具顺序读取，若恰逢刷新导致状态变化，稳定后重新检查。
7. **受影响业务抽测**：在批准范围内检查受影响的国内直连、境外代理、Azure AI 精确规则及保留例外对应业务。记录具体网站/操作、预期、实际结果和时间，避免泄露账号数据。检查器不发业务请求；网站成功也不能证明 DNS 配置已经全部加载。未完成抽测不得把关键规则检查写成网站兼容性通过。
8. **失败恢复并复验**：按下表恢复对应来源，再执行已批准的重新应用，随后重复步骤 6、7。原变更单元已授权同范围失败回滚时不重复申请；未授权或范围扩大则先确认。缺少备份、关联不一致或写入结果不明时停止，不猜测恢复命令。

### 恢复哪些来源

| 变更类型 | 变更前保留 | 失败后的人工恢复与重新应用 |
|---|---|---|
| 仅修改关联脚本 | 原 JS 的完整内容（包括手动直连管理区）、当前索引和关联关系；同时确认其他来源未变化 | 在确认目标后，将原内容恢复至同一活动脚本编辑器并保存；保存可能立即应用。再核验生成文件、运行态和业务。其他来源已变化时不能声称仅恢复 JS 足够。 |
| 更新远程订阅 | 更新前的原始订阅文件、`profiles.yaml` 及全部关联扩展；同一恢复点的生成配置仅用于比较，不代替来源 | 将备份的订阅内容恢复至当前索引所指向的原订阅文件；核对更新前后索引元数据和关联扩展，仅按授权恢复受影响部分。随后重新激活该订阅以执行扩展、生成并应用；不要点击远程更新来恢复，否则会再次下载。具体写入路径和操作方式须在该变更单元中按当前版本核实。 |
| 同时修改多个来源 | 上述材料及所有获准修改项的同一恢复点 | 恢复全部受影响来源及必要关联，再重新应用；不能用一个 JS 文件撤销所有订阅更新。 |

恢复文件只证明磁盘来源已恢复；重新应用后仍必须验证内核运行态。生成文件不是完整备份，不能直接覆盖它来宣称恢复成功。本文没有通用备份/恢复 CLI：检查器未实现这些参数，不能猜测写入命令、控制 socket 或用未经核实的 GUI 导入代替来源恢复。实际备份和恢复未在阶段 2B-2 执行或演练。

### 当前保护范围

手动流程只覆盖按上述流程执行的变更。**当前 sub 已本地化且自动刷新关闭，但没有自动业务验收保障**：没有自动阻止错误业务配置应用，也没有自动验收或自动恢复。以后若要改变这些行为，需要单独确定方案和授权。

后续网站兼容性检查应继承当前目标、版本、检查时间、逐项问题/必要未知、关键规则与出口证据及 DNS 未暴露限制。阶段 2B-2 的工具和流程交付本身不表示已完成网站抽测，也不表示所有自动更新受到保护；后续已有证据见本文“已有证据与未验证边界”。

## 阶段 6D-1：离线双节点候选（历史技术说明）

以下保留候选构建与复验边界；双节点接入及手动备用基础验证已完成，当前日常操作见本文开头，不再按候选接入计划重复实施。

默认 `clash_audit.py` 仍不执行 JavaScript、不保存或应用配置，schema v1 与退出码不变。
节点身份现在有明确边界：原 sub 的唯一洛杉矶 VMess/WS/TLS 身份、可选的指定 E-IX 新加坡 AnyTLS。
显示名称不能替代身份；当前 WS 传输对象固定为已核实结构，新增传输参数须重新审阅。
生成节点的全部字段（除已定义的重命名）必须与来源递归类型严格一致。备用节点只在
当前关联 proxies 扩展的 `append` 维护，并与当前索引中的 E-IX 唯一指定节点比较，不能自动跟随更新。

| 状态 | 主组完整候选 | 八个跟随组 | 境外、gfw、fallback DNS |
|---|---|---|---|
| 原单节点 `legacy` | 洛杉矶、DIRECT，洛杉矶首位 | 保留已核实旧候选及顺序 | 固定洛杉矶 |
| 过渡单节点 `transition` | 仅洛杉矶 | 仅主组 | 主组 |
| 目标双节点 `dual` | 洛杉矶、新加坡，洛杉矶首位 | 仅主组 | 主组 |

八组为 AI、电报、油管、奈飞、巴哈姆特、国外媒体、谷歌 FCM、漏网之鱼。移除这些组的
DIRECT/固定节点旁路是明确的候选语义变化。其他业务组保留直连、拒绝及默认顺序，其代理选项
统一跟随主组。原单节点兼容不适用于含第二节点的配置；候选标记存在却返回旧拓扑也不能通过。
所有业务组、DNS 出口、规则目标、dialer 引用均检查有效性；未选分支也检查循环。运行态核对
全部组候选与当前选择、全部节点的同名协议类型，以及八组、主组和三处境外 DNS 的最终叶节点。
内核自动提供的 `PASS-RULE` 等已核实内置出口不被当成未知订阅节点。

`candidate_topology.js` 是供私有候选组装的无凭据实现片段，不是活动脚本，也不是自动加载插件。
`candidate.py` 只提供显式离线组装/执行函数；`build_script` 要求旧辅助函数指纹匹配，再仅替换
`simplifyLosAngelesNode` 和相关引用辅助函数。管理区、包装入口和 UID 原样保留。身份、重名、
旧别名或未知引用异常时可能保留输入，由检查器拒收；**这种返回行为不能阻止 Clash 应用**。
候选原入口函数按本阶段已核实指纹冻结，注释调用或提前返回不能通过关联检查。
检查器主入口没有调用这些函数。Node 的 vm 仅隔离变量；执行进程另由 macOS 沙箱禁止网络及所有文件写入。
此入口仅用于本机选定的候选，不承诺不可信脚本的完整安全隔离（例如读权限并未封闭）。

候选目录必须是 Clash 既有备份目录下独立的 `stage6d-candidate-*`，目录 700、文件 600。
其中包含候选 JS、候选 proxies YAML、必要原来源快照、修改前工具快照和脱敏 `manifest.json`。
真实凭据不得进入仓库或输出；清单记录来源/候选/工具指纹与验证摘要，私有包不写活动索引。

显式复验已有私有包（仅读包和当前来源，仅写入自动回收的私有临时目录）：

```sh
# 将下列路径替换为本阶段回执中的准确候选目录，不使用活动 profiles 目录。
/usr/bin/python3 -B scripts/local/clash_audit/verify_candidate.py '/absolute/private/stage6d-candidate-TIMESTAMP'
```

该复验入口输出独立的脱敏候选摘要，退出 0 表示离线复验通过、1 表示拒收；它不是审计器的
schema v1 接口，不提供应用功能。复验包含：当前来源与原快照指纹、确定性候选构建、纯
`clash_direct` 脚本解析/重绘兼容、Node 语法、完整脚本幂等、三态离线检查、两出口模拟选择、
全部规则与 DNS 最小差异断言、三次 Mihomo `-t`。只使用本机 Node、PyYAML、Mihomo 和 Geo
资源，不安装、不下载。macOS `sandbox-exec` 明确拒绝网络，文件写入仅允许本次临时目录；
缺少此能力或资源时拒收，不退回可联网校验。不启动候选内核、不读取额外运行态接口。

离线组装从原 sub、关联扩展和全局 merge 构造输入，先用原脚本重现活动规则、节点、组和 DNS。
已核实的 GUI 差异为 `Rule` → `rule` 归一化及补充 `dns.enhanced-mode: fake-ip`；生成文件仅用于
对比，不充当新订阅来源。模拟执行不等于在 Clash 的 Boa 引擎真实应用；`-t` 仅证明配置可解析。

以下为 6D-1 当时提出的 6D-2 接入计划，记录历史阶段边界，不是当前待执行步骤：

1. 核对当前索引、原 sub、五项关联与全局扩展、E-IX 保存文件及候选/工具指纹；运行真实旧配置
   的离线和运行态检查。来源变化、确定问题或新增必要未知须先处理，不能沿用旧快照授权。
2. 在批准的变更单元内建立当时的恢复点，包含来源、选择及直连工具状态。
3. 先保存候选脚本并重新激活本地 sub，验收过渡单节点；确认默认洛杉矶及三处 DNS 引用。
4. 通过后再保存候选 proxies 扩展并重新激活本地 sub，验收双节点且仍选择洛杉矶。
   不点击远程更新；保存本身也可能触发生成/应用，不能当作离线预览。
5. 真实新加坡切换、新连接/DoH 链与冷缓存节点解析验收留给后续获准阶段；回滚顺序为先恢复
   洛杉矶选择、撤回备用，再恢复旧脚本并重新应用复验，实际动作仍须在批准范围内。

UDP、吞吐或长期稳定性。四个 GET 不暴露完整节点传输字段，也不能证明旧 DoH/TCP 连接已清除。

`runtime_observed=true`、`runtime_verified=false`；不能把私有候选或模拟成功写成备用已接入。
