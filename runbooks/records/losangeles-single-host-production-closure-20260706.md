# LosAngeles 单机生产收尾与日常运维清单

更新时间：2026-07-06 04:05 UTC
服务器：`LosAngeles`
模型：单机生产服务器

> 历史边界：本文件记录 2026-07-06 第一轮单机生产收尾。2026-07-18 第二轮治理已启动，当前状态与新验收门禁见 `losangeles-round2-governance-20260718.md`；第二轮完成前不要沿用本文件的“最终状态”作为当前 100% 完成结论。

## 1. 收尾结论

LosAngeles 当前按“单机生产服务器”模型已经完成本轮建设，可以进入日常维护阶段。

已完成的闭环包括：

- 安全基线：SSH、UFW、Fail2ban、公网端口收敛、敏感凭据 root-only。
- 服务治理：Nginx 统一入口、服务目录规范化、Docker 运行边界、日志轮转。
- 备份体系：本机备份、Cloudflare R2 异地备份、R2 生命周期策略。
- 恢复验证：本机恢复、R2 拉回、Redis ACL 隔离恢复、Postgres 隔离导入、应用级恢复。
- 可观测性：Prometheus、Grafana、Alertmanager 邮件、Loki、主机/容器/数据库/Redis/Nginx/证书/安全日志/业务健康监控。
- 治理留痕：`/opt/ops` Git 化、runbook、状态文档、验收矩阵、变更提交。

## 2. 当前能力边界

当前不是高可用集群，也不是多机灾备接管架构。

准确边界是：

- 单机正常运行时：具备监控、告警、备份、恢复、日志、安全和变更留痕。
- 应用或数据误操作时：可从本机备份或 R2 备份恢复。
- 主机彻底损坏时：R2 中有异地备份，已有跨机器恢复预案，但需要临时购买或准备新机器后执行。
- 不承诺秒级切换、自动故障转移、多可用区高可用或双活。

因此，跨机器实机恢复不是当前单机模型的完成门槛，而是未来有第二台主机或明确高可用预算后的升级项。

## 3. 风险接受项

| 项目 | 当前结论 | 后续触发条件 |
| --- | --- | --- |
| 单机无 HA | 风险接受 | 有第二台主机、业务 SLA 提升或预算允许时再做 |
| SSH 来源 IP 未限制 | 风险接受 | 有固定出口 IP 后限制 `22/tcp` 来源 |
| 云厂商无安全组/快照/审计 | 厂商能力限制 | 更换云厂商或增加第二层云侧能力时再补 |
| 云厂商账单/到期治理 | 用户要求暂缓 | 需要自动续费、余额、欠费、到期提醒时单独处理 |
| 无独立数据盘 | 风险接受 | 数据增长、磁盘压力升高或迁移维护窗口出现时规划 `/data` |
| 主机名不规范化 | 风险接受 | 后续维护窗口且确认影响面后再改 |
| Redis 分用户 ACL | 应用侧待配合 | `sub2api` 支持 Redis username 后再拆分 |
| `sub2api` runtime 低权限 | 应用侧待配合 | 上游支持 migration-only 或关闭启动自动 migration 后再切 |

## 4. 日常运维节奏

### 每日或看到告警时

- 查看 Alertmanager 邮件是否有 firing 告警。
- 打开 Grafana：
  - `LosAngeles Host Overview`
  - `LosAngeles Services and Backups`
  - `LosAngeles App and Business Health`
  - `LosAngeles Security Overview`
- 优先确认：
  - 主机 CPU / 内存 / 磁盘 / inode。
  - Docker 容器是否 down 或反复重启。
  - 备份和 R2 同步是否过期。
  - HTTPS 探针、业务 health、Nginx 5xx 是否异常。
  - Fail2ban 是否有异常集中封禁。

### 每周

- 只读查看 `/opt/ops` 状态，确认没有未提交变更。
- 抽看 Grafana 的备份新鲜度、数据库、Redis、证书、业务健康面板。
- 抽查 `/var/log/backup` 是否有新的失败日志。
- 查看 R2 同步指标是否持续更新。

### 每月

- 做一次系统更新评估，必要时安排维护窗口。
- 检查磁盘容量、inode、Docker volume 增长趋势。
- 抽查一个最新 `.sql.gz` 和一个 `.tar.gz` 备份完整性。
- 检查 Cloudflare Origin Certificate 和公网证书剩余天数。
- 复核告警噪声，必要时调整 Alertmanager 路由或阈值。

### 每季度或重要变更后

- 做一次只读恢复演练抽检，优先验证 R2 可拉回。
- 复核 `/opt/ops` runbook 是否仍符合真实运行状态。
- 复核云厂商账号 MFA、API Key、绑定邮箱和手机号。
- 如果业务增长明显，重新评估独立数据盘和第二台主机需求。

## 5. 变更纪律

- 变更前先看 `/opt/ops` 文档和当前运行配置。
- 高风险操作先确认影响、验证和回滚方案。
- 涉及配置文件时，先测试再 reload / restart。
- 变更后必须验证服务健康、监控指标和关键入口。
- 变更后同步 `/opt/ops`，提交并推送 GitHub。
- 不把 R2、SMTP、数据库、Grafana、证书私钥等凭据写入 Git、聊天或截图。

## 6. 当前不要做

- 没有固定出口 IP 前，不限制 SSH 来源。
- 没有第二台主机前，不把跨机器恢复当成本轮未完成项。
- 没有维护窗口前，不改主机名、不迁移数据盘、不强切数据库用户。
- 不随手删除本机备份或 R2 对象。
- 不把临时恢复容器发布到公网。
- 不放宽 `/opt/ops`、备份脚本、secret 文件权限。

## 7. 后续项目触发条件

| 后续项目 | 何时启动 |
| --- | --- |
| 跨机器实机恢复 | 有临时新机器或第二台长期主机时 |
| 高可用 / 多机部署 | 业务 SLA、收入或用户量要求更高可用时 |
| SSH 固定 IP 限源 | 有稳定出口 IP 时 |
| 账单 / 到期治理 | 需要自动续费和欠费提醒闭环时 |
| 门户网站 | `www.areasong.top` 内容和部署方案确定时 |
| Redis 分用户 ACL | 应用支持 username 或可改配置时 |
| `sub2api` runtime 低权限 | 应用支持 migration/runtime 分离后 |
| 独立数据盘 | 数据增长、备份窗口变长或磁盘压力升高时 |

## 8. 最终状态一句话

LosAngeles 已完成单机生产服务器的安全、备份、恢复、监控、告警、文档和变更闭环；后续进入例行维护，新增工作按业务需求或外部条件单独立项。
